# Специфікація вимог до програмного забезпечення (SRS)

**Система:** ProvaTrace – незалежний сервіс для побудови та перевірки криптографічно верифікованих випадкових процесів
**Стандарт:** ISO/IEC/IEEE 29148:2018
**Версія документа:** 1.0
**Статус:** Approved

**Трасування:** вимоги цього документа походять із Core Features та NFRs підрозділу 1.5 ([1_analysis.md](1_analysis.md)) і реалізуються в архітектурі Розділу 2 ([2_design.md](2_design.md)). Обґрунтування ключових технологічних рішень – у каталозі [adr/](adr/).

---

## 1. Контекст системи (System Context)

### 1.1 Призначення

ProvaTrace формує випадкові результати операцій для зовнішніх систем-інтеграторів і надає незалежний криптографічний доказ коректності як самого результату, так і параметрів ймовірнісної моделі, за якою його інтерпретовано.

### 1.2 Межі системи (Scope)

У межах системи:

- керування ключами підпису систем-інтеграторів та їх сертифікація кореневим ключем;
- реєстрація, валідація, комітмент і версіонування конфігурацій ймовірнісних моделей;
- життєвий цикл seed-пар: створення, генерація результатів, розкриття;
- публічний реєстр і механізм верифікації;
- кабінет власника системи-інтегратора.

Поза межами системи:

- облікові записи кінцевих учасників (ідентифікатор учасника передається системою-інтегратором як непрозорий рядок);
- платіжні операції та будь-які грошові розрахунки;
- користувацький інтерфейс системи-інтегратора.

### 1.3 Зовнішні сутності

| Сутність | Тип | Взаємодія з системою |
|---|---|---|
| Бекенд системи-інтегратора | Зовнішня система | REST / HTTPS, автентифікація API-ключем: generate, roll, reveal, реєстрація конфігурацій |
| Власник системи-інтегратора | Користувач | Кабінет власника через браузер, вхід через OIDC |
| Перевіряючий (учасник, аудитор) | Анонімний користувач | Публічний реєстр і сторінка верифікації, без автентифікації |
| Адміністратор ProvaTrace | Внутрішній користувач | Онбординг, сертифікація та відкликання ключів, моніторинг |
| Identity Provider (OIDC) | Зовнішня система | Автентифікація власників систем-інтеграторів, видача JWT |
| CDN (Cloudflare) | Зовнішня система | Кешування публічного реєстру та статичних клієнтських застосунків |

### 1.4 Обмеження середовища

- Демонстраційне розгортання – один хост з Docker Compose; продуктивні метрики доступності (SRS-NFR-REL-01) задаються для цільового розгортання з кількома репліками.
- Генерація результату вимагає доступу до секретного seed, тому не може виконуватися на стороні системи-інтегратора (модель довіри, підрозділ 1.4.4).

## 5. Глосарій (Glossary)

| Термін | Визначення |
|---|---|
| Seed-пара | Сукупність секретного `server_seed`, його хешу (commitment), значення `client_seed` і лічильника `nonce`, що використовуються для серії операцій до розкриття |
| Commitment | Опублікований до початку операцій хеш секретного значення, що доводить незмінність цього значення після розкриття |
| Nonce | Монотонний лічильник операцій у межах seed-пари; гарантує унікальність входу HMAC для кожної операції |
| HMAC-SHA256 | Код автентичності повідомлення на основі SHA-256 і секретного ключа (RFC 2104); у системі – детермінована функція отримання випадкового числа |
| Rejection sampling | Метод відбору значень, що відкидає частину вихідного простору для усунення статистичного зміщення операції залишку від ділення (modulo bias) |
| Ed25519 | Схема цифрового підпису на кривій Edwards25519 (RFC 8032) з детермінованим підписом довжиною 64 байти |
| RFC 8785 (JCS) | JSON Canonicalization Scheme – правила однозначної серіалізації JSON для обчислення хешів і підписів |
| Vault Transit | Модуль HashiCorp Vault, що виконує криптографічні операції над даними без видачі ключів застосунку |
| p95 Latency | Значення затримки, яке не перевищують 95% запитів за період вимірювання |
| RPO / RTO | Recovery Point Objective – допустимий обсяг втрачених даних у часі; Recovery Time Objective – допустимий час відновлення |
| Ідемпотентність | Властивість операції, за якої повторне виконання з тими самими вхідними даними не змінює стан системи повторно |
